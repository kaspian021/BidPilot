# چک‌لیست رفتن به حالت live

هدف: اولین پیشنهاد واقعی را با کمترین ریسک بفرستید.

## ۰) پیش‌نیازها

همه‌ی این‌ها را `bidpilot setup` یا خود ربات تلگرام (`/setup`) می‌پرسد؛ فایل `.env` لازم نیست.
بعداً هم از تلگرام قابل تغییرند (`/status`).

| مورد | از کجا |
|---|---|
| توکن ربات تلگرام | `@BotFather` → `/newbot` (در `bidpilot setup` بفرستید) |
| `chat_id` | به ربات `/start` بدهید؛ خودکار ثبت می‌شود |
| حساب سایت | کوکی `PHPSESSID` (DevTools → Cookies) یا نام کاربری/رمز — در setup یا `/market` |
| پروفایل واقعی | در setup یا `/profile` — رزومه PDF یا لینک گیت‌هاب/پورتفولیو بفرستید تا خودکار پر شود (یا دستی) |
| لحن و سبک | در setup یا `/style` — بگویید چطور و با چه لحنی پیشنهاد بنویسد |
| درصد قیمت | در setup یا `/style` — چند درصد بودجه‌ی کارفرما پیشنهاد شود (پیش‌فرض ۶۰٪، همیشه داخل بازه) |
| کلید LLM رایگان | Groq / Gemini / OpenRouter / … — در setup یا `/llm`؛ بدون آن هم قالب فارسی کار می‌کند |
| خواندن PDF رزومه | بسته‌ی `pypdf` — ربات در اولین فایل خودکار نصبش می‌کند؛ وضعیت/نصب دستی: `/deps` یا `bidpilot deps --install` |

```bash
bidpilot setup --status   # آماده است؟ چه چیزی مانده؟
```

## ۰٫۵) جست‌وجوی هوشمند

اگر کلید AI ثبت شده باشد (و در `sources/<site>/config.yaml` مقدار `discovery.mode`
روی `auto` یا `ai` باشد)، هر دور جست‌وجو با مدل انجام می‌شود: مدل از صفحه‌ی اصلی شروع
می‌کند، فهرست‌های «مرتبط با تخصص» و «همه‌ی پروژه‌های باز» را از لینک‌های واقعی سایت
پیدا می‌کند و صفحه‌ی هر پروژه را می‌خواند. نتیجه را در `/preview` می‌بینی
(«🧭 n صفحه خوانده شد، m پروژه پیدا شد»).

- سهمیه‌ی رایگان: هر جست‌وجو حدود ۱۰ تا ۱۵ درخواست به مدل می‌زند؛ با `reuse_seconds: 600`
  حداکثر هر ۱۰ دقیقه یک‌بار. برای کم‌کردن مصرف: `max_steps`/`max_detail_pages` را کم کن.
- بدون کلید یا با `discovery.mode: selectors` رفتار قبلی (سلکتورهای CSS) برمی‌گردد.
- برای اطمینان از اینکه مدل واقعاً سایت را می‌فهمد، یک‌بار `/preview` بگیر و خروجی را ببین.

## ۱) اجرای آزمایشی

```bash
bidpilot selftest                # تست واقعی: تلگرام + کلید AI + سایت + یک پیشنهاد نمونه (بدون ارسال)
bidpilot doctor                  # همه‌ی ردیف‌ها OK؟ (منبع parscoders باید پروژه پیدا کند)
bidpilot telegram-test           # پیام تست رسید؟
bidpilot preview -s parscoders --limit 2    # متن‌ها را بخوانید؛ لحن و قیمت درست است؟
bidpilot once --dry-run --limit 3           # چرخه‌ی کامل بدون ارسال
```

اگر لحن متن‌ها هنوز شبیه شما نیست، در تلگرام `/style` را بزنید و دستور سبک خودتان را
بنویسید؛ دوباره `/preview` بگیرید. (لحن آزاد با مدل زبانی اعمال می‌شود؛ بدون کلید،
قالب ثابت فارسی استفاده می‌شود.)

## ۲) تأیید ورود و شروع فعالیت

قبل از هر ارسال، مطمئن شوید ربات **واقعاً وارد حساب شده است** — در تلگرام:

```
/check     → «✅ وارد حساب شما شدیم — پارس‌کدرز» + تعداد پروژه‌های خوانده‌شده
```

اگر منفی بود، `/market` را بزنید و کوکی تازه بدهید. بعد از سبز شدن:

```
🚀 شروع فعالیت   (یا /run)
```

خلاصه‌ی نهایی (سایت، درصد قیمت، لحن، فاصله، سقف روزانه، حالت آزمایشی/واقعی) را نشان
می‌دهد؛ با «تأیید و شروع» رصد در همان ربات بالا می‌آید و اولین نتیجه در چت گزارش می‌شود.
توقف فوری: `/stop`.

> 🔒 **قفل امنیتی:** اگر حالت 🔴 واقعی باشد و هنوز هیچ `/preview` موفق یا دور 🧪 آزمایشی
> انجام نشده باشد، ربات `run` را باز نمی‌کند و دو دکمه نشان می‌دهد: «🧪 پیش‌نمایش همین حالا»
> و «🔁 اجرای یک دور آزمایشی». پس از یک آزمایش موفق (همان سایت)، `/run` واقعی باز است.
> این قفل با عوض‌کردن سایت فعال دوباره بسته می‌شود.

## ۳) فعال‌سازی حالت واقعی

```bash
bidpilot go-live      # چک‌لیست را اجرا و config/config.local.yaml را می‌سازد
bidpilot once --limit 1        # فقط یک پیشنهاد واقعی
```

یا بدون ترمینال: در تلگرام `/mode` → «واقعی». رصدکننده‌ی در حال اجرا، تغییر را
در دور بعدی خودکار می‌گیرد. (اگر هنوز آزمایش بی‌خطر انجام نشده باشد، ربات به‌جای شروع
`/preview` یا یک دور آزمایشی پیشنهاد می‌کند.)

بعد از دیدن نتیجه در تلگرام و روی سایت:

```bash
bidpilot run          # اجرای دائمی
```

بازگشت فوری به حالت آزمایشی: `bidpilot go-live --off`

## ۴) تنظیمات محافظه‌کارانه‌ی پیشنهادی برای شروع

```yaml
runtime:
  max_bids_per_hour: 3
  max_bids_per_day: 15
  min_seconds_between_bids: 300     # ۵ دقیقه بین پیشنهادها
  poll_interval_seconds: 180
filters:
  min_budget: 400000                # زیر ۴۰۰ هزار تومان پیشنهاد نده
  require_budget: true              # پروژه‌ی بدون بودجه‌ی اعلام‌شده را رد کن
  require_skill_match: true         # پروژه باید مهارتی از پروفایل را داشته باشد
  skill_keywords: []                # خالی = خودکار از پروفایل (استک + نقش)
runtime:
  notify_digest: true               # یک گزارش گروه‌بندی‌شده در هر دور، نه پیام برای هر پروژه
```

هفته‌ی اول: روزی ۵ تا ۱۵ پیشنهاد با کیفیت، بهتر از ۵۰ پیشنهاد تکراری است.

## ۵) نشانه‌های هشدار

- پیام «نشست پارس‌کدرز منقضی شده» ← کوکی را به‌روز کنید.
- پیام «فرم ارسال پیشنهاد پیدا نشد» ← ظاهر سایت عوض شده: `bidpilot inspect -u <آدرس پروژه>` و اصلاح YAML.
- پیام «سقف ساعتی/روزانه پر شده» ← طبیعی است، یعنی ترمز کار می‌کند.
- «متن تولیدشده اعتبارسنجی را رد کرد» ← `proposal.on_generation_failure: "template"` را بگذارید یا مدل را عوض کنید.

## ۶) بازبینی هفتگی

```bash
bidpilot stats     # چند پروژه دید، چند پیشنهاد رفت، چند تا رد شد
```

اگر نرخ پاسخ کارفرما پایین بود: `pricing.ratio` را کمی پایین بیاورید (مثلاً ۰.۴) یا متن‌ها را با `preview` بازبینی کنید.

## ۷) اخلاق و قوانین

- پیشنهاد تکراری/کپی برای همه‌ی پروژه‌ها = سوختن اعتبار شما. سقف‌ها را کم نگه دارید.
- ادعای نمونه‌کار جعلی نکنید (پروفایل truthful باشد).
- شرایط استفاده‌ی سایت را بخوانید؛ مسئولیت ارسال خودکار با خودتان است.
