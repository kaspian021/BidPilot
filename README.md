# BidPilot 🚀

**ربات هوشمند پیشنهاددهی برای پارس‌کدرز (و هر مارکت‌پلیس دیگری) — بدون دخالت شما.**

پروژه‌های جدید سایت را زنده رصد می‌کند، متن پروژه را می‌خواند، قیمت را **داخل بازه‌ی اعلامی کارفرما** انتخاب می‌کند، یک پیشنهاد فارسی اختصاصی برای همان پروژه می‌نویسد، ارسال می‌کند و نتیجه را در **تلگرام** به شما اطلاع می‌دهد.

```
┌──────────────┐   ┌──────────┐   ┌────────┐   ┌────────────┐   ┌──────────┐   ┌──────────┐
│  Parscoders  │──▶│  Filter  │──▶│ Dedupe │──▶│  Pricing   │──▶│ Proposal │──▶│  Submit  │
│  (scrape)    │   │ (rules)  │   │ (SQL)  │   │ in range   │   │  (LLM)   │   │ +Notify  │
└──────────────┘   └──────────┘   └────────┘   └────────────┘   └──────────┘   └──────────┘
        ▲                                                                          │
        │                                                                          ▼
   scheduler (poll every N sec, jittered)                                   Telegram + DB
```

## چرا افزونه‌ی مرورگر نه؟

افزونه‌ی کروم فقط وقتی کار می‌کند که مرورگر باز و لاگین باشد. خواسته‌ی شما «حتی وقتی من در سایت نیستم» است، پس این یک **سرویس سمت‌سرور** است: روی یک VPS ارزان (یا Raspberry Pi/لپ‌تاپ همیشه‌روشن) اجرا می‌شود، ۲۴ ساعته رصد می‌کند و به تلگرام شما پیام می‌دهد.

## ⚡ شروع سریع (۳ دقیقه، بدون `.env`)

```bash
git clone https://github.com/<username>/bidpilot.git && cd bidpilot
python3 -m venv .venv && source .venv/bin/activate     # ویندوز: .venv\Scripts\activate
pip install -e ".[dev]"

bidpilot setup     # توکن تلگرام، کلید هوش مصنوعی رایگان، حساب سایت، پروفایل (PDF/لینک)، لحن، درصد قیمت
bidpilot bot       # کنترل کامل از تلگرام؛ با «🚀 شروع فعالیت» رصد هم از همان چت بالا می‌آید
```

**هیچ فایل `.env` لازم نیست.** `bidpilot setup` فقط از خودت می‌پرسد و هر پاسخ را
بلافاصله در `data/settings.json` ذخیره می‌کند (پوشه `0700`، فایل `0600`، در `.gitignore`).
بعداً هر چیزی را می‌توانی از داخل تلگرام عوض کنی؛ لازم نیست سرور را دست بزنی.

اولین بار که به ربات پیام می‌دهی، همان چت به‌عنوان «مالک» ثبت می‌شود و بقیه نمی‌توانند
دستور بدهند. هر وقت خواستی: `bidpilot setup --status` وضعیت را نشان می‌دهد.

### ۱) هوش مصنوعی رایگان و همیشگی

BidPilot با هر API سازگار با OpenAI کار می‌کند، اما پیش‌فرض‌ها روی سرویس‌هایی هستند که
**توکن رایگان با اعتبار ماندگار** می‌دهند (بدون کارت بانکی):

| سرویس | گرفتن کلید رایگان | مدل پیش‌فرض | نکته |
|---|---|---|---|
| **Groq** (پیش‌فرض) | [console.groq.com/keys](https://console.groq.com/keys) | `openai/gpt-oss-120b` | سریع‌ترین؛ سقف درخواست روزانه دارد |
| **Google Gemini** | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | `gemini-3.8-flash` | سهمیه‌ی رایگان روزانه |
| **OpenRouter** | [openrouter.ai/keys](https://openrouter.ai/keys) | `openrouter/free` | روتر خودکار مدل‌های `:free` |
| **Mistral** | [console.mistral.ai](https://console.mistral.ai/api-keys) | `mistral-small-latest` | حالت Free با محدودیت نرخ |
| **Ollama** (محلی) | — | `qwen2.5:14b` | بدون کلید، بدون اینترنت، بدون محدودیت |

> نام درست سرویس **Groq** است (با q)؛ محصول xAI که «Grok» نام دارد API رایگان دائمی ندارد.
> سقف رایگان یعنی ممکن است در ساعات شلوغ محدود شوی؛ برای همین `llm.fallbacks` می‌تواند
> کلید Gemini/OpenRouter را هم در اولویت دوم امتحان کند. اگر همه‌شان در دسترس نباشند،
> متن با قالب فارسی داخلی نوشته می‌شود و هیچ پیشنهادی از دست نمی‌رود.
> اگر سرویسی مدلی را بازنشسته کرد، فقط `llm.model` را عوض کن
> (`bidpilot settings set llm.model -v "…"`) — هیچ کدی نباید تغییر کند.

کلید در `bidpilot setup` یا با `/llm` در تلگرام گرفته و ذخیره می‌شود؛
`bidpilot doctor` و `/test` سالم بودنش را چک می‌کنند.

### اگر ترجیح می‌دهی از `.env` استفاده کنی (اختیاری)

`setup` را دوست نداری؟ همان کار با `.env` هم انجام می‌شود (فقط آن را `chmod 600` کن و
کامیت نکن). این‌ها کافی است:

```env
TELEGRAM_BOT_TOKEN="123456789:AA…"     # از @BotFather
TELEGRAM_CHAT_IDS="111222333"           # یا بعداً /start بده تا خودکار پر شود
LLM_API_KEY="gsk_…"                     # کلید رایگان Groq (provider پیش‌فرض همین است)
PARSOCODERS_COOKIE="PHPSESSID=…"        # یا PARSOCODERS_USERNAME/PASSWORD
```

> نکته: اگر هم `.env` و هم `data/settings.json` مقدار داشته باشند، **settings.json برنده
> است** (چون آخرین تنظیم کاربر است). برای پاک‌کردن یک مقدار ذخیره‌شده:
> `bidpilot settings unset llm.api_key`.
> مقدار `LLM_PROVIDER` در `.env` خوانده نمی‌شود؛ برای عوض‌کردن سرویس از
> `bidpilot settings set llm.provider -v gemini` یا `/llm` استفاده کن.

### ۲) اتصال تلگرام

1. در تلگرام به [`@BotFather`](https://t.me/BotFather) پیام بده → `/newbot` → توکن را بگیر.
2. توکن را در `bidpilot setup` بفرست (یا `/setup` داخل ربات).
3. به ربات خودت `/start` بده؛ `chat_id` خودکار ثبت می‌شود.

از آن به بعد همه‌چیز در چت است: `/status`، `/style`، `/profile`، `/llm`، `/market`،
`/preview`، `/filters`، `/deps`، `/mode`، `/test`. راهنمای کامل: `bidpilot bot` و `/help`.

اگر فایل PDF رزومه خوانده نشود، ربات **صادق** می‌ماند: می‌گوید چرا (نصب نبودن `pypdf`،
اسکن‌شده بودن، رمز داشتن) و «✅ ذخیره شد» نمی‌فرستد؛ اطلاعات قبلی پروفایل هم دست‌نخورده
می‌ماند و همان فایل در صف می‌ماند تا بعد از رفع مشکل دوباره تلاش شود. برای PDF متنی،
ربات بسته‌ی `pypdf` را خودش نصب می‌کند (نصب در همان محیط مجازی BidPilot).

**قبل از ارسال واقعی، یک آزمایش بی‌خطر لازم است.** تا وقتی یک `/preview` موفق یا یک دور
🧪 آزمایشی کامل نشود، `/run` در حالت 🔴 واقعی باز نمی‌شود؛ این‌طور پیشنهادِ ناقص روی حساب
شما ثبت نمی‌شود. اگر هوش مصنوعی جواب ندهد، دلیل واقعی خطا (کلید نامعتبر، سهمیه تمام‌شده، …)
همان‌جا در چت نشان داده می‌شود و متن از قالب آماده ساخته می‌شود.

### 🔎 جست‌وجوی هوشمند در سایت (AI browsing)

اسکراپر قدیمی فقط همان صفحه‌ای را می‌خواند که به آن گفته بودیم؛ نتیجه: بودجه «اعلام نشده»،
پروژه‌های بی‌ربط و پیشنهاد برای «طراحی لوگو» از طرف یک برنامه‌نویس موبایل. حالا وقتی کلید
هوش مصنوعی رایگان ثبت شده باشد، **مدل خودش داخل سایت (با حساب و کوکی خودت) می‌گردد**:

1. از صفحه‌ی اصلی شروع می‌کند و از لینک‌های واقعی همان صفحه، فهرست‌ها را پیدا می‌کند
   — فهرست «مرتبط با تخصص من» و «همه‌ی پروژه‌های باز»؛ هیچ URL‌ای دستی به پرامپت داده نشده.
2. صفحه‌ی پروفایل را می‌خواند تا بداند تخصص ثبت‌شده‌ی تو چیست.
3. صفحه‌ی هر پروژه را باز می‌کند و **عیناً از متن** برمی‌دارد: عنوان، توضیحات کامل، بودجه‌ی
   کارفرما، زمان تحویل، مهارت‌ها، دسته و کارفرما.
4. بعد از آن مسیر همیشگی: فیلتر (بودجه + مهارت) → قیمت = درصدی از بودجه‌ی کارفرما →
   نوشتن پیشنهاد با لحن خودت → ارسال.

مدل هیچ آدرسی از خودش نمی‌سازد (فقط لینک‌های شماره‌دارِ همان صفحه)، هیچ عددی از خودش
نمی‌سازد (بودجه با پارسر فارسی خودمان خوانده می‌شود) و کل گردش سقف دارد:

| تنظیم در `sources/<site>/config.yaml` | پیش‌فرض | معنی |
|---|---|---|
| `discovery.mode` | `auto` | `auto` = AI اگر کلید باشد؛ `ai` = همیشه؛ `selectors` = فقط سلکتورهای CSS |
| `discovery.seed_paths` | `["/"]` | نقطه‌ی شروع؛ بقیه‌ی مسیرها را مدل پیدا می‌کند |
| `discovery.max_steps` | `8` | حداکثر صفحه‌ای که در یک دور باز می‌شود |
| `discovery.max_detail_pages` | `4` | حداکثر صفحه‌ی پروژه که کامل خوانده می‌شود |
| `discovery.max_projects` | `4` | سقف پروژه‌های جمع‌آوری‌شده در هر دور |
| `discovery.reuse_seconds` | `600` | نتیجه تا این مدت دوباره استفاده می‌شود (سهمیه‌ی رایگان نسوزد) |
| `discovery.page_delay_seconds` | `1` | فاصله‌ی درخواست‌ها |
| `discovery.tokens_per_minute` | `7000` | سقف توکن در دقیقه؛ برنامه قبل از هر درخواست صبر می‌کند تا 429 نگیریم |
| `discovery.brief` | متن فارسی | «منطق سایت» برای مدل — بدون آدرس؛ قابل ویرایش |

اگر مدل خطا بدهد، سهمیه تمام شود یا `mode: selectors` باشد، همان اسکراپر سلکتوری قبلی
کار می‌کند؛ یعنی این قابلیت یک مسیر بهتر است، نه یک نقطه‌ی شکست تازه.

**سهمیه‌ی «توکن در دقیقه» (429):** سهمیه‌ی رایگان Groq عدد سختی دارد — ۸٬۰۰۰ توکن در
دقیقه، حتی برای `gpt-oss-20b`. برای همین دو کار انجام می‌شود: (۱) پرامپت‌ها کوچک‌اند
(صفحه‌ی فهرست فقط «لینک‌ها» را می‌فرستد، نه متن کاملش) و (۲) کلاینت مدل قبل از هر درخواست
یک بودجه‌ی غلتانِ یک‌دقیقه‌ای نگه می‌دارد و اگر جا نباشد **صبر می‌کند**؛ اگر باز هم 429
برسد، به‌جای ۱٫۵ ثانیه، همان مدتی صبر می‌کند که خود سرویس می‌گوید (`retry-after`).
اگر عجله داری، `discovery.max_detail_pages` یا `discovery.max_projects` را کم کن.

برای دیدن همین گردش از ترمینال (بدون تلگرام):

```powershell
.venv\Scripts\python.exe -m bidpilot explore              # سایت فعال
.venv\Scripts\python.exe -m bidpilot explore -s ponisha --propose   # + یک پیشنهاد آزمایشی
```

در `/preview` دقیقاً می‌بینی چه اتفاقی افتاده: «🧭 ۷ صفحه خوانده شد، ۴ پروژه پیدا شد
(۱۲ درخواست به مدل)» — و اگر جست‌وجو شکست بخورد، دلیل واقعی‌اش را می‌بینی.

### فیلتر پروژه‌ها — بودجه و مهارت

دو قاعده به‌صورت پیش‌فرض روشن‌اند و از `/filters` در تلگرام (یا بخش `filters` تنظیمات)
قابل تغییرند:

| قاعده | پیش‌فرض | یعنی چه |
|---|---|---|
| `filters.require_budget` | روشن | پروژه‌ای که بودجه‌اش اعلام نشده باشد بررسی نمی‌شود — قیمت حدسی نمی‌دهیم |
| `filters.require_skill_match` | روشن | پروژه باید دست‌کم یکی از مهارت‌های `/profile` را داشته باشد |

کلیدواژه‌های مهارت خودکار از پروفایل (استک + نقش) ساخته می‌شوند؛ لازم نیست لیست دستی بنویسید.
برای بازسازی از پروفایل: دکمه‌ی «♻️ بازسازی از پروفایل» در `/filters` یا
`bidpilot settings set filters.skill_keywords -v ""`.

گزارش هر دور هم گروه‌بندی شده است: به‌جای یک پیام برای هر پروژه، یک پیام «📊 گزارش دور»
با تعداد بررسی‌شده/جدید/ارسال/رد و دلیل ردها می‌آید (`runtime.notify_digest`، پیش‌فرض روشن).

### ۳) سایت فریلنسری و حساب کاربری — چند سایت، یک سایت فعال

سه سایت از پیش ثبت شده‌اند (`bidpilot settings sites`):

| سایت | آدرس | وضعیت سلکتورها |
|---|---|---|
| پارس‌کدرز | `parscoders.com` | تنظیم‌شده و تست‌شده |
| پونیشا | `ponisha.ir` | آماده؛ نیاز به کالیبراسیون اولیه با `bidpilot inspect -s ponisha` |
| کارلنسر | `karlancer.com` | آماده؛ نیاز به کالیبراسیون اولیه با `bidpilot inspect -s karlancer` |

در هر لحظه **یک** سایت فعال است و بقیه خاموش‌اند. عوض کردنش:

```
/sites                 → لیست هر سه سایت + وضعیت حساب هرکدام (دکمه‌ها = سوییچ)
/site ponisha          → سایت فعال را پونیشا کن
/market                → سایت را انتخاب کن و روش ورود/کوکی همان سایت را بده
```

از ترمینال هم همین کار:

```bash
bidpilot settings sites            # چه سایت‌هایی ثبت شده‌اند، کدام فعال است
bidpilot settings use ponisha      # عوض کردن سایت فعال
```

**حساب هر سایت جداست** — کوکی پارس‌کدرز هیچ‌وقت برای پونیشا فرستاده نمی‌شود.
برای هر سایت یکی از این دو روش:

- **کوکی نشست** (ساده‌تر، پیشنهادی): در مرورگر لاگین کن → DevTools → Application →
  Cookies → کوکی نشست (معمولاً `PHPSESSID`) را کپی کن و در `/market` بفرست.
- **نام کاربری و رمز**: ربات خودش لاگین می‌کند؛ اگر سایت کپچا داشت، کوکی بهتر است.

> کوکی مثل «رمز موقت» است؛ هرگز کامیت یا به کسی داده نمی‌شود. اگر منقضی شد،
> ربات در تلگرام خبر می‌دهد و با `/market` مقدار جدید همان سایت را می‌فرستی.
> سرور شبیه‌سازی وضعیت هر سه سایت: `bidpilot selftest -s <site>`.

### ۳٫۵) پروفایل: یک فایل یا یک لینک کافی است

لازم نیست نام، سابقه، مهارت‌ها و نمونه‌کارها را دستی تایپ کنی. در `/setup` (یا `/profile`)
یکی از این‌ها را انتخاب کن:

| گزینه | چه می‌فرستی | چه چیزی استخراج می‌شود |
|---|---|---|
| **رزومه PDF** (پیشنهادی) | فایل PDF رزومه را به‌صورت Document در تلگرام بفرست | نام، تخصص، سال سابقه، مهارت‌ها، نمونه‌کارها، لینک |
| **گیت‌هاب** | `https://github.com/username` | نام/بیو + مخزن‌های عمومی و توضیحاتشان |
| **پورتفولیو** | لینک سایت شخصی | متن صفحه (اسکریپت‌ها حذف می‌شوند) |
| **ورود دستی** | خودت تایپ می‌کنی | همان سؤال‌های قبلی |

استخراج با **همان کلید هوش مصنوعی رایگان** انجام می‌شود که در مرحله‌ی ۱ دادی؛ پرامپت
صریحاً می‌گوید چیزی از خودش نسازد. بعد از تحلیل، خلاصه‌ی استخراج‌شده را در چت می‌بینی
و هر وقت خواستی با `/profile` اصلاحش می‌کنی. اگر کلید/شبکه در دسترس نباشد، یک
استخراج‌کننده‌ی ساده‌ی محلی (بدون شبکه) جایگزین می‌شود.

> فایل رزومه در `data/uploads/` (gitignored) نگه داشته می‌شود و جایی ارسال نمی‌شود
> جز همان درخواست تحلیل به سرویس هوش مصنوعی.

### ۴) لحن، سبک و درصد قیمت (دلخواه)

این بخش دقیقاً همان چیزی است که می‌خواهی: **به ربات بگو چگونه پیشنهاد بدهد.**

در تلگرام `/style` را بزن؛ یکی از لحن‌های آماده را انتخاب کن یا لحن دلخواهت را بنویس،
و در قدم بعد هر دستور سبکی داری بفرست:

```
/style
→ ۳) خودمانی و گرم
→ «همیشه اول یک سؤال درباره‌ی ددلاین بپرس، روی تحویل مرحله‌ای تأکید کن،
   از تعریف‌کردن از کارفرما پرهیز کن و جمله‌ها کوتاه باشند.»
```

در ادامه‌ی همان `/style` یک سؤال قیمت هم می‌آید: **چند درصد از بودجه‌ی اعلامی کارفرما
را پیشنهاد بدهیم؟** (۱۰ تا ۱۰۰، پیش‌فرض ۶۰). اگر کارفرما بازه بدهد، همان درصد از بازه
انتخاب می‌شود و پیشنهاد هرگز از بازه بیرون نمی‌زند:

| درصد | بودجه ۵۰۰٬۰۰۰–۱٬۵۰۰٬۰۰۰ | معنی |
|---|---|---|
| ۳۰٪ | ۸۰۰٬۰۰۰ تومان | رقابتی‌تر |
| ۵۰٪ | ۱٬۰۰۰٬۰۰۰ تومان | وسط بازه |
| ۹۰٪ | ۱٬۴۰۰٬۰۰۰ تومان | گران‌تر، سیگنال سینیوریتی |

همین کار از ترمینال:

```bash
bidpilot settings set pricing.ratio -v 0.6      # ۶۰٪ بودجه
bidpilot settings set proposal.tone -v "خودمانی و گرم"
bidpilot settings set proposal.style_instructions \
  -v "همیشه روی تحویل مرحله‌ای تأکید کن و از تعریف از کارفرما پرهیز کن."
```

این لحن و دستورها مستقیم داخل پرامپت مدل زبانی می‌روند (و بر لحن پیش‌فرض پروفایل اولویت دارند).
برای دیدن نتیجه: `/preview` در تلگرام یا `bidpilot preview --limit 2`.

### ۵) 🚀 شروع فعالیت (از داخل تلگرام)

بعد از این‌که تنظیمات کامل شد، ربات **خودش ورود به حساب سایت را بررسی می‌کند** و می‌گوید:

```
✅ وارد حساب شما شدیم — پارس‌کدرز
📋 ۲۴ پروژه در صفحه‌ی اول خوانده شد.
```

بعد دکمه‌ی **«🚀 شروع فعالیت»** ظاهر می‌شود. با زدنش یک خلاصه‌ی نهایی می‌بینی (سایت،
درصد قیمت، لحن، فاصله‌ی بررسی، سقف روزانه، حالت آزمایشی/واقعی) و با «تأیید و شروع»
رصد پروژه‌ها در همان فرایند ربات بالا می‌آید:

- اولین نتیجه بلافاصله در چت گزارش می‌شود: چند پروژه بررسی شد، چند پیشنهاد ساخته/ارسال شد.
- `/stop` متوقف می‌کند، `/run` دوباره شروع، `/check` فقط ورود را دوباره می‌سنجد.
- اگر کوکی منقضی شود، پیام خطا + راهنمای `/market` می‌آید.

```bash
bidpilot bot          # ربات؛ بعد در چت «🚀 شروع فعالیت»
bidpilot bot --run    # ربات + شروع خودکار رصد از همان لحظه‌ی روشن شدن
bidpilot run          # فقط رصد، بدون ربات (ترمینال جدا)
```

### ۶) حالت ارسال

پیش‌فرض **آزمایشی** است: پیشنهاد ساخته می‌شود، در تلگرام می‌بینی، ولی چیزی روی سایت ثبت نمی‌شود.
وقتی راضی بودی:

```bash
bidpilot go-live       # چک‌لیست ایمنی + فعال‌سازی
bidpilot go-live --off # بازگشت فوری به آزمایشی
```

یا بدون ترمینال، در تلگرام: `/mode` → «واقعی».
راهنمای محافظه‌کارانه: [`docs/GO_LIVE_CHECKLIST.md`](docs/GO_LIVE_CHECKLIST.md)

```bash
bidpilot demo          # اجرای کامل روی داده‌ی آزمایشی، بدون شبکه و بدون حساب
bidpilot doctor        # بررسی سلامت تنظیمات و دسترسی‌ها
bidpilot once --dry-run
bidpilot run           # اجرای دائمی؛ یا: bidpilot bot --run (ربات + رصد با هم)
```

## 🧪 چطور واقعاً تست کنم؟

سه لایه‌ی تست وجود دارد؛ از بی‌خطر به واقعی:

**۱) بدون هیچ حساب و اینترنت (سلامت خود برنامه):**

```bash
bidpilot selftest --offline   # منبع آزمایشی + متن قالبی، بدون شبکه
bidpilot demo                 # یک چرخه‌ی کامل روی داده‌های نمونه
```

**۲) با تنظیمات واقعی، ولی بدون ارسال هیچ پیشنهادی:**

```bash
bidpilot setup                # یا /setup داخل ربات — همه‌چیز را یک‌بار وارد کن
bidpilot selftest             # تست واقعی: توکن تلگرام + کلید AI + خواندن سایت + ساخت یک پیشنهاد
bidpilot preview -s parscoders --limit 2   # متن‌ها را بخوان
bidpilot once --dry-run --limit 3          # کل چرخه، بدون ارسال
```

`selftest` هیچ‌چیز روی سایت ثبت نمی‌کند: توکن تلگرام را با `getMe` می‌سنجد، یک پیام تست
می‌فرستد (`--no-telegram-message` اگر نمی‌خواهی)، کلید AI را با یک درخواست کوچک واقعی
تست می‌کند، صفحه‌ی پروژه‌ها را می‌خواند و یک پیشنهاد نمونه می‌سازد. اگر همه‌ی ردیف‌ها
سبز/زرد باشند، آماده‌ای. (`--offline` برای وقتی است که هنوز هیچ حساب/کلیدی نداری.)

**۳) اولین پیشنهاد واقعی (فقط وقتی متن‌ها را پسندیدی):**

```bash
bidpilot go-live              # چک‌لیست ایمنی را اجرا می‌کند
bidpilot once --limit 1       # فقط یک پیشنهاد واقعی، بعد نتیجه را در سایت ببین
```

یا بدون ترمینال: `/mode` در تلگرام → «واقعی»، بعد `bidpilot once --limit 1` را اجرا کن
(یا ربات را با `bidpilot bot --run` بالا بیاور تا خودش هر چند دقیقه یک دور بزند).
بازگشت فوری: `bidpilot go-live --off` یا `/mode` → «آزمایشی».

### ویندوز: خطای `pip` هنگام نصب

اگر `pip install -e ".[dev]"` با این خطا متوقف شد:

```
Could not import runpy._run_module_as_main
SyntaxError: source code string cannot contain null bytes
```

این خطا **از پروژه نیست**؛ یعنی نصب پایتونِ روی سیستم (فایل‌های stdlib مثل `runpy.py`)
خراب است — معمولاً نسخه‌ی Microsoft Store، آنتی‌ویروس، یا نصب ناقص. سه راه، به ترتیب:

**۱) اسکریپت آماده (پیشنهادی):**

```powershell
powershell -ExecutionPolicy Bypass -File scripts\windows-setup.ps1
```

خودش پایتون را چک می‌کند، venv می‌سازد، نصب می‌کند و `selftest --offline` می‌گیرد.

**۲) دستی با `python -m pip` (هیچ‌وقت `pip` خالی را صدا نزن):**

```powershell
where python
python -VV
python -c "import runpy; print(runpy.__file__)"   # اگر خطا داد: پایتون خراب است
$env:PYTHONHOME=""                                 # اگر ست شده بود
$env:PYTHONPATH=""
py -3.12 -m venv .venv
.\.venv\Scripts\activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install -e ".[dev]"
```

اگر `python -c "import runpy"` خطا داد، پایتون را از
[python.org](https://www.python.org/downloads/windows/) (نه Microsoft Store) دوباره نصب کن
و «Add python.exe to PATH» را تیک بزن. مسیر پروژه را هم از `Downloads\Compressed\...`
به یک مسیر ساده مثل `C:\dev\bidpilot` منتقل کن.

**۳) اجرا بدون نصب (وقتی pip اصلاً کار نمی‌کند):**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\activate
python -m pip install httpx pydantic pydantic-settings sqlalchemy aiosqlite jinja2 typer rich `
  tenacity beautifulsoup4 lxml python-dateutil jdatetime orjson PyYAML pypdf
$env:PYTHONPATH="src"
python -m bidpilot selftest --offline
python -m bidpilot setup
```

`python -m bidpilot …` دقیقاً همان `bidpilot …` است؛ فقط به‌جای نصب editable از پوشه‌ی
`src` import می‌کند.

### اگر چیزی سبز نشد

| پیام | معنی و راه‌حل |
|---|---|
| `توکن نامعتبر است` | توکن ربات را دوباره از @BotFather بگیر: `bidpilot setup --stage telegram` |
| `chat_id ثبت نشده` | در تلگرام به ربات `/start` بده (خودکار ثبت می‌شود) |
| `401/403` از سرویس AI | کلید اشتباه/کامل نبودن؛ `/llm` یا `bidpilot setup --stage llm` |
| `429` از سرویس AI | سهمیه‌ی رایگان همان لحظه پر است (Groq: ۸٬۰۰۰ توکن/دقیقه). برنامه خودش صبر می‌کند و از سلکتورها ادامه می‌دهد؛ اگر زیاد تکرار شد کلید دوم (Gemini) را در `/llm` اضافه کن |
| `صفحه لیست باز شد اما هیچ پروژه‌ای…` | ظاهر سایت عوض شده: `bidpilot inspect -s <site>` و اصلاح `sources/<site>/config.yaml` |
| `نشست منقضی شده` | کوکی `PHPSESSID` را تازه کن: `/market` → روش کوکی |
| `فرم ارسال پیشنهاد پیدا نشد` | قبلاً برای این پروژه پیشنهاد داده‌ای یا سلکتورها عوض شده‌اند |
| `نسخه‌ی قدیمی اجرا می‌شود` (پیام‌ها با نسخه‌ی پوشه فرق دارد) | `python -m bidpilot` نسخه‌ی نصب‌شده در site-packages را اجرا می‌کند: `bidpilot doctor --fix` (یا همان دستوری که خودش نشان می‌دهد) |
| `بسته‌ی pypdf برای خواندن PDF نصب نیست` | ربات خودش نصبش می‌کند؛ اگر نشد در تلگرام `/deps` یا `bidpilot deps --install` (هر دو روی همان پایتونی که ربات با آن اجرا شده نصب می‌کنند) یا `/profile` → لینک گیت‌هاب/پورتفولیو/ورود دستی |

پیش از هر تست واقعی، یک بکاپ از `data/settings.json` بگیر (همه‌ی اعتبارنامه‌ها همان‌جاست)
و مطمئن شو `runtime.submit_mode` روی `dry_run` است تا وقتی خودت نخواهی چیزی ارسال نشود.

## 🧠 متن پیشنهاد چطور ساخته می‌شود؟

ساختار ثابت است (همان چیزی که خواسته‌اید) و محتوا از **متن همان پروژه** می‌آید:

```
سلام و وقت بخیر
من … هستم، برنامه‌نویس … با … سال تجربه در …   →  معرفی (فقط از پروفایل ذخیره‌شده)
درباره‌ی «عنوان پروژه» … ۳ تا ۵ چالش کلیدی + راه‌حل هر کدام   →  از تحلیل پروژه
جمع‌بندی: قیمت پیشنهادی … تومان، زمان تحویل … روز، آمادگی شروع
با احترام، …
```

- **با کلید LLM رایگان** (Groq / Gemini / OpenRouter / Mistral / Ollama): متن طبیعی، مخصوص همان پروژه و با **لحن و دستورهای سبک خودت**؛ اگر سرویس اصلی سقف بخورد، سرویس بعدی امتحان می‌شود.
- **بدون کلید LLM**: یک موتور قالب + «بانک دانش» فارسی (playbook) که بر اساس کلیدواژه‌های پروژه (ربات، درگاه، ووکامرس، API، سئو، …) چالش و راه‌حل متناسب می‌نویسد. خروجی همیشه معتبر و پروژه‌محور است (لحن آزاد فقط با LLM اعمال می‌شود).
- هر متن قبل از ارسال **اعتبارسنجی** می‌شود؛ اگر رد شد، یک بار بازنویسی درخواست می‌شود و در نهایت به قالب برمی‌گردد.

### تنظیم قیمت

```yaml
pricing:
  strategy: "midpoint_round"   # midpoint_round | aggressive_low | premium_high | fixed
  ratio: 0.5                   # 0.0 = کف بازه، 0.5 = وسط، 1.0 = سقف بازه
  min_step: 5000               # رند کردن به عدد انسانی
  delivery_days: 14
```

| بازه‌ی کارفرما | ratio=0.5 | ratio=0.15 | ratio=0.85 |
|---|---|---|---|
| ۵۰۰,۰۰۰ – ۱,۵۰۰,۰۰۰ | **۱,۰۰۰,۰۰۰** | ۶۵۰,۰۰۰ | ۱,۳۵۰,۰۰۰ |
| ۲ – ۴ میلیون | ۳,۰۰۰,۰۰۰ | ۲,۳۰۰,۰۰۰ | ۳,۷۰۰,۰۰۰ |
| توافقی | `default_amount` | | |

قیمت هرگز از بازه بیرون نمی‌زند؛ حتی در استراتژی «fixed» هم به بازه clamp می‌شود.
پارسر بودجه فارسی است: `۵۰۰,۰۰۰ تا ۱,۵۰۰,۰۰۰ تومان`، `۵۰۰ تا ۱۵۰۰ تومن`، `۳۰۰ تا ۷۰۰ هزار`، `۲ تا ۴ میلیون`، `۵,۰۰۰,۰۰۰ ریال`، `توافقی`.

## 🧩 افزودن یک سایت جدید

معمولاً فقط یک `config.yaml`: `bidpilot inspect -s <site>` برای پیدا کردن سلکتورها،
یک `adapter.py` دوازده‌خطی که همان YAML را به `HtmlMarketSource` می‌دهد، و یک خط
ثبت در `registry.py`. اگر سایت API رسمی دارد، آداپتور سفارشی بنویس:

```python
# src/bidpilot/sources/mysite/adapter.py
from ..base import Source
from ..registry import register_source

@register_source("mysite")
class MySiteSource(Source):
    async def fetch_projects(self):
        html = await self.get_html("/jobs")
        return parse_jobs(html)          # -> list[Project]

    async def submit_bid(self, project, proposal, amount, delivery_days):
        ...                              # -> SubmissionResult
```

```yaml
# config/config.yaml
sources:
  - type: "mysite"
    enabled: true
    settings: {}
```

و تمام: قیمت‌گذاری، تولید متن، ضدتکرار، تلگرام و دیتابیس همان‌طور کار می‌کنند. راهنمای کامل: [`docs/ADD_A_SOURCE.md`](docs/ADD_A_SOURCE.md).

## 🖥️ دستورهای CLI

| دستور | کار |
|---|---|
| `bidpilot setup` | ویزارد کامل (بدون `.env`): تلگرام، LLM رایگان، حساب سایت، پروفایل (PDF/لینک)، لحن، درصد قیمت |
| `bidpilot setup --status` | وضعیت راه‌اندازی و مقادیر ذخیره‌شده |
| `bidpilot bot` | ربات کنترل تلگرام (راه‌اندازی/لحن/وضعیت/پیش‌نمایش) |
| `bidpilot bot --run` | همان ربات + شروع خودکار رصد (داخل ربات هم `/run` و `/stop` هست) |
| `bidpilot selftest [--offline] [-s site]` | تست واقعی تلگرام، کلید AI، سایت و ساخت یک پیشنهاد (بدون ارسال) |
| `bidpilot version` | نسخه + مسیری که کد از آن اجرا می‌شود (برای تشخیص نسخه‌ی قدیمی نصب‌شده) |
| `bidpilot deps [--install]` | وضعیت/نصب بسته‌های اختیاری (مثل `pypdf` برای خواندن رزومه‌ی PDF) |
| `bidpilot settings show/set/unset/path` | مدیریت تنظیمات ذخیره‌شده از ترمینال |
| `bidpilot settings sites` | لیست سایت‌ها، سایت فعال و وضعیت حساب هرکدام |
| `bidpilot settings use <site>` | عوض کردن سایت فعال (همان `/site` در تلگرام) |
| `bidpilot demo` | اجرای کامل روی داده‌ی آزمایشی (بدون شبکه) |
| `bidpilot doctor [--fix]` | بررسی سلامت: پروفایل، تلگرام، LLM، pypdf، دسترسی منابع و **اینکه کدام نسخه واقعاً اجرا می‌شود** (`--fix` نسخه‌ی نصب‌شده‌ی قدیمی را با همین پوشه جایگزین می‌کند) |
| `bidpilot once [--live] [--limit N]` | یک دور کامل |
| `bidpilot run` | اجرای دائمی (daemon) |
| `bidpilot preview -s parscoders --limit 2` | دیدن متن پیشنهادی بدون ارسال/ذخیره |
| `bidpilot explore [-s site] [--propose]` | تماشای جست‌وجوی هوش مصنوعی: چه صفحه‌هایی باز شد، از هر پروژه چه بودجه/مهلتی خوانده شد (بدون تلگرام) |
| `bidpilot stats` | آمار پروژه‌ها و پیشنهادها |
| `bidpilot telegram-whoami` / `telegram-test` | راه‌اندازی و تست تلگرام |
| `bidpilot go-live` / `--off` | چک‌لیست ایمنی + فعال/غیرفعال کردن ارسال واقعی |
| `bidpilot inspect [-s site] [-u <url>] [-f file]` | دیباگ سلکتورها وقتی ظاهر سایت عوض شده |
| `bidpilot sources` / `initdb` | منابع ثبت‌شده / ساخت جدول‌ها |

## 🚀 اجرای دائمی

```bash
# Docker (ساده‌ترین)
docker compose run --rm bidpilot setup   # یک بار: پاسخ‌ها در volume «./data» می‌مانند
docker compose up -d --build
docker compose logs -f

# یا systemd روی VPS
sudo cp deploy/bidpilot.service /etc/systemd/system/
sudo systemctl enable --now bidpilot
journalctl -u bidpilot -f
```

اگر می‌خواهی ربات کنترل هم بالا باشد، در `docker-compose.yml` مقدار
`command: ["bot", "--run"]` را اضافه کن (یا `bidpilot bot --run` را در systemd بگذار).

برای مقیاس بزرگ‌تر: `DATABASE_URL=postgresql+asyncpg://...` و چند نمونه‌ی worker (dedupe از طریق unique index دیتابیس تضمین می‌شود). جزئیات: [`docs/DEPLOY.md`](docs/DEPLOY.md).

## ⚠️ نکات مهم و مسئولیت‌پذیری

- **قوانین سایت**: ارسال خودکار پیشنهاد ممکن است خلاف قوانین پارس‌کدرز یا مخل تجربه‌ی کارفرما تلقی شود. قبل از `live` کردن، شرایط استفاده‌ی سایت را بخوانید و ریسک را خودتان بپذیرید. توصیه: فاصله‌ی منطقی، سقف روزانه‌ی کم، و بازبینی دوره‌ای متن‌ها.
- **کیفیت پیشنهاد**: پیشنهاد خودکار باید صادق باشد. پروفایل و نمونه‌کارها را در `bidpilot setup` (یا `/profile`) واقعی وارد کنید؛ ادعای نمونه‌کار جعلی هم به شما آسیب می‌زند هم به کارفرما.
- **کوکی/توکن** = اعتبارنامه. تنظیمات در `data/settings.json` (chmod 600) ذخیره می‌شوند و پوشه‌ی `data/` در `.gitignore` است؛ اگر از `.env` استفاده می‌کنی (اختیاری) آن را هم هرگز کامیت نکن.
- **تغییر ظاهر سایت** ممکن است پارسر را بشکند؛ `bidpilot doctor` و لاگ‌ها سریع خبر می‌دهند و اصلاح با ویرایش YAML ممکن است.
- این پروژه **ابزار** است، نه مجوز نقض قوانین سایت‌ها.

## 📤 انتشار روی گیت‌هاب

این پروژه در همین workspace آماده است؛ برای ساختن ریپازیتوری روی حساب خودتان:

```bash
# روش ۱ — توکن (بدون نصب هیچ ابزاری)
export GH_TOKEN=ghp_xxxxxxxxxxxxxxxxx      # توکن با دسترسی repo
./scripts/publish_to_github.sh bidpilot private

# روش ۲ — GitHub CLI
gh auth login
./scripts/publish_to_github.sh bidpilot private
```

اسکریپت خودش `git init`، کامیت، ساخت ریپازیتوری و push را انجام می‌دهد و در پایان لینک را چاپ می‌کند.
(فایل `.env` و پوشه‌ی `data/` هرگز push نمی‌شوند.)

> اگر ارتباط GitHub را در تنظیمات Arena وصل کنید، خودم ریپازیتوری را می‌سازم و push می‌کنم.
